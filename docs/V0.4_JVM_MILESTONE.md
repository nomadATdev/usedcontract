# UsedContract v0.4 JVM Milestone

## Why JVM first

The purpose of v0.4 is not to maximize language count. It is to validate the hardest technical claim on a runtime with mature instrumentation support and common enterprise usage.

Provider implementation language is irrelevant. UsedContract instruments the consumer and emits a language-neutral IR.

## Target architecture

```text
Provider response
      |
      v
HTTP client / Spring stack
      |
      v
Jackson deserialization
      |
      +---- provenance attachment
      |
      v
Application value use
      |
      +---- field/getter read
      +---- equality / null / enum / numeric operation
      +---- control-flow evidence where feasible
      |
      v
UsedContract Java Agent
      |
      v
Semantic Event IR
      |
      v
Collector
      |
      v
Contract inference
      |
      v
Candidate mutation / replay
      |
      v
Consumer-impact report
```

## Core correctness property

UsedContract must distinguish provider schema difference from observed consumer dependency. A field changing is not sufficient to call a change breaking. The tool must link the changed value to an observed requirement of a real consumer execution.

## Minimum evidence record

```json
{
  "consumer": "checkout-service",
  "version": "1.0",
  "endpoint": "GET /account",
  "path": "$.status",
  "operation": "equals",
  "operand": "ACTIVE",
  "control_influence": true
}
```

## Engineering constraints

- No manually authored Pact-style contract in the demo.
- No claim of whole-program taint analysis unless demonstrated.
- Do not export full response bodies by default.
- Reuse the existing semantic IR; the JVM agent is an adapter, not a second compatibility engine.
- Tests must include both true-positive and non-breaking cases.

## Success criteria

v0.4 succeeds only if CI demonstrates:

1. automatic observation of a meaningful response-field dependency;
2. inference of the dependency into UsedContract's contract store;
3. detection of a semantic-breaking mutation;
4. non-breaking treatment of a removed, unobserved field;
5. no application-level calls to UsedContract's event-emission API in the demo business logic.

## After v0.4

If successful, implement the same semantic contract in .NET. Cross-runtime equivalence is more important than adding superficial SDKs.
