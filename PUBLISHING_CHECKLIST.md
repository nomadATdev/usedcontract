# First-publication checklist

- [ ] Confirm the repository name (`usedcontract` recommended).
- [ ] Replace the generic Licensor wording in `LICENSE` with your legal name or
      company/entity name before signing paid commercial-license agreements.
- [ ] Enable GitHub Actions.
- [ ] Enable GitHub Private Vulnerability Reporting.
- [ ] Enable Discussions if you want RFC/Q&A traffic.
- [ ] Add repository topics: `api-testing`, `contract-testing`,
      `breaking-changes`, `runtime-analysis`, `microservices`, `rest-api`,
      `dynamic-analysis`, `observability`, `java-agent`, `dotnet`, `python`,
      `golang`, `developer-tools`, `ci-cd`.
- [ ] Set About description:
      `Runtime-derived API compatibility contracts that detect semantic breaking changes from real consumer behavior.`
- [ ] Create GitHub Release `v0.3.2` using `RELEASE_NOTES_v0.3.2.md`.
- [ ] Upload the release ZIP and SHA-256 as Release assets, not source files.
- [ ] Add a 1280x640 social preview after the repository exists.
- [ ] Call the project `source-available`, not `open source`, while BUSL-1.1 applies.
- [ ] Do not claim `world's first`, patent novelty or production-grade semantic
      taint tracking.
